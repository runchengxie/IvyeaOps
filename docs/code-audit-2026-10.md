# Code and architecture audit, 2026-10

## Scope and evidence

The audit began at `50d0a20` on the fork's `main`. The worktree was clean. `origin` is `runchengxie/IvyeaOps` and `upstream` is `Hector-xue/IvyeaOps`. There is no `.gitmodules`, gitlink or submodule checkout. No other repository was modified or initialized.

The local runtime used Python 3.12.13 and IvyeaAgent 1.16.9 from upstream's `v1.16.9` archive. The Agent is an external dependency, not a submodule. CI resolves its latest release independently and can fall back to `main`; this is a reproducibility risk. The candidate environment used Python 3.11.15, FastAPI 0.162.0, Starlette 1.10.0, Pillow 13.0.0 and the same IvyeaAgent version.

## Data flow and boundaries

The eMAG collectors use fixed RO read endpoints, reject incomplete pagination and project selected fields. Complete evidence is imported by `store_artifacts` as a source-labelled snapshot; reports and manual job receipts reference snapshot IDs. The administrator workspace reads those artifacts, and MCP has scoped snapshot/report tools. Snapshot format currently has no `schema_version`. Local issue approvals and execution records do not call a marketplace write endpoint. Sequential pages are not an atomic marketplace snapshot.

The fork still mounts Amazon and legacy Listing routes, and startup still initializes Amazon-related services. The frontend retains `/legacy/*` routes. These are active consumers, not proven dead code. Before retiring them, inventory API, CLI, scheduled job, data and skill consumers; establish eMAG equivalents and document migration and retention. This audit does not claim complete eMAG marketplace coverage.

## Findings and changes

- `app/services/emag_readonly.py`: `math.isfinite` raised `OverflowError` for very large integer stock. Preserve nonnegative integer classification without converting it to float; a regression test observed the failure first.
- `app/tests/test_static_mime.py`: a subprocess inherited the caller's working directory and could not import `app` from the repository root. Set its working directory explicitly; the original assertion remains unchanged. The initial full baseline therefore had one invocation-dependent test failure.
- The API description identified the whole project as an Amazon hub despite the eMAG workspace. It now describes the current eMAG and legacy marketplace scope.
- `scripts/install.sh`: the optional GitHub proxy used `git config --global`, persisting a rewrite in the user's Git configuration. The replacement is scoped to the installer process and children; a real Git subprocess test verifies prior process settings and the absence of a global file write. The installer also detects versioned Python, rejects old environments and bootstraps missing pip when possible; synthetic installer tests preserve an existing `.env`. The application package rejects Python 3.10 and older before loading services.
- The Python 3.12 runtime audit found five distinct Starlette advisories (reported as ten entries); installed FastAPI 0.128.8 constrained Starlette below 1.0. Python 3.10 resolved Pillow 12.3.0 with 39 advisories in the tested environment. With owner approval, the candidate requires Python 3.11+, pins the tested FastAPI/Starlette/Pillow versions and retains existing data and configuration while requiring a backup/recreated old virtual environment. See [ADR-0043](decisions/0043-python-security-migration.md).
- The first Python 3.11 full run had 32 failures. SOCKS proxy configuration exposed a missing `socksio` runtime dependency; the related 76 tests passed after adding `httpx[socks]`. New FastAPI route internals also invalidated cockpit test dependency discovery. Those tests now use signed sessions and real requests for every documented cockpit and Lingxing operation, including an unprotected-route negative control. The eMAG/Agent contract subset passed 51 tests against the fixed Agent version.
- The server sample is now `configs/server.env.example`; source and frozen release consumers are documented. The root Docker sample belonged to retired deployment and was removed. Actual `.env` files, credentials and data were not moved.

## Baselines and limits

- Original full backend invocation from repository root: 1292 passed, 1 skipped and 1 failed in 662.70 s. The MIME test passed from the CI working directory. The invocation issue was subsequently fixed.
- Ruff passed with the existing configured scopes. Frontend npm audit found zero vulnerabilities; i18n contracts passed 8 tests, render contracts 2, and the error-text gate passed.
- `uv pip check` found 89 original installed packages compatible. The isolated Python 3.11 candidate had 78 compatible packages and no known advisories in `pip-audit` after adding SOCKS support. This does not audit uninstalled or future dependency versions.
- `ty check src/server/app` reported 203 diagnostics in both environments. A normalized comparison found three new platform/version-specific messages and two resolved messages. `os.listdrives` has a fallback on Python 3.11; `os.set_blocking` is used by POSIX terminal paths. Existing diagnostics remain and `ty` is not a configured CI gate. The prior environment and the candidate have different platform-sensitive messages even though the total is unchanged.
- Git-tracked Python sources contained 241 `noqa`, 8 `type: ignore`, 6 `pragma: no cover`, 4 explicit `pytest.skip` and 3 `skipif` occurrences at baseline. Most `noqa` entries target BLE001, which is not selected by the current Ruff rules. These counts are an inventory, not a claim that every exception was individually resolved.
- Initial candidate coverage was 56% for `app`, including tests within that tree, and the run failed. After fixes, a full Python 3.11 run recorded 1297 passed, 1 platform skip and 19 warnings in 558.99 s, with 57% coverage for the same scope. That run started before the final installer and application-entry guard additions. The final focused suite covering runtime guards, installer behavior, frozen Agent, eMAG, MIME and cockpit permissions passed 58 tests with one Starlette TestClient deprecation warning. No coverage threshold is configured. Original-environment coverage was not measured before changes.
- A read-only `ruff --isolated --select F841` check found eight ignored unused assignments. `listing/visuals.py` computes `profile_anchors` and `ref_text` without consuming them; their intended product behavior is not established. Other assignments call functions that may validate or have side effects. They were not removed mechanically.
- AST triage of the 221 `BLE001`-annotated handlers found 89 with logging calls, 20 containing a raise, and 112 other fallback/propagation cases. This is a mechanical categorization, not an individual safety guarantee. Non-BLE suppressions mainly cover delayed imports, compatibility re-exports and framework method names. The six coverage pragmas cover an environment fallback, debug representation, command-line entry, two defensive exception paths and one test-only branch; these remain existing exclusions. Skips are tied to unavailable browsers, PowerShell, platform-specific permissions or zstd; no existing skip was widened.
- Static size inspection identified large modules including `ai_synthesis_service.py` (2151 lines) and `html_report.py` (1549 lines). Size alone does not establish a safe refactoring boundary. No module was split solely to improve a metric.
- Browser/provider/model operations, actual eMAG write actions and deployment were not exercised. The final repository CI run is separate from these local results. The existing running environment is not upgraded by this changeset. Unexecuted release packaging and the complete platform matrix require their own checks.
